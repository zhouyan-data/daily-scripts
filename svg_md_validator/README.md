# LLM 结构化文档校验：双载体（结构文件 + 注解文件）一致性检查

> 灵感来源：博客园《让大模型读懂一张施工图：SVG+MD 双载体记录法的踩坑笔记》
> 核心思想迁移到数据分析场景：给 LLM 喂结构化文档（如财务报表演示文件）时，
> 不要只给一份几何/渲染文件（"骨"），还要给一份语义注解文件（"魂"），
> 用同一套 ID 互联，写入前先做机器可测的一致性校验。

## 核心原则（四条）

1. **单一事实源**：每类信息只在一处为真，另一处只引用。
2. **ID 互联而非值复制**：两边不重复存数值，映射关系单独存 crosswalk。
3. **冲突裁决规则前置**：几何以骨为准，值与语义以魂为准——写在代码里，不靠模型猜。
4. **两源独立读 + 背靠背核对**：对不上就标记 `unclear`，绝不臆造。

## 文件结构

```
svg_md_validator/
├── validator.py        # 主校验器
├── sample_bone.json    # 模拟 SVG（骨：几何/坐标）
├── sample_soul.json    # 模拟 MD（魂：语义/注解）
└── crosswalk.json      # ID 映射表
```

## 跑法

```bash
python validator.py            # 默认校验 sample_*
python validator.py bone.json soul.json crosswalk.json
```

## 验收口径（从原文学来的）

模型说"读到了什么"不算数，要机器能核对：
- 每个语义条目能定位到骨中的具体元素（ID 可达）
- 每条尺寸/数值在两源独立读取后背靠背一致，不一致进 `unclear` 列表
- 上下文预算：切片按 `data-view` 分组注入，整份大文件永不一次性进 prompt

跑完输出三行账：total / matched / unclear。unclear 不丢人，编数才丢人。
